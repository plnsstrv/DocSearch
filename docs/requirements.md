# DocSearch — требования к системе

Версия 0.2 от 21.10.2026. Черновик для согласования с заказчиком.

Документ фиксирует, что должна делать система и с каким качеством. У каждого требования есть идентификатор, приоритет и способ проверки. Устройство системы описывается отдельно: диаграммы, модель данных, API.

## 1. Термины

| Термин | Значение |
|---|---|
| Скан | PDF без текстового слоя: страницы — картинки |
| OCR | Распознавание текста на картинке (Tesseract) |
| CER | Доля ошибочно распознанных символов относительно эталонного текста |
| FTS5 | Встроенный в SQLite полнотекстовый поиск |
| Recall@5 | Доля контрольных запросов, для которых правильный документ попал в первые 5 результатов |
| MoSCoW | Приоритеты: **M** — обязательно в MVP, **S** — желательно в MVP, **C** — после MVP, **W** — не в этой версии |

## 2. Проблема и цели

Архив юриста — бумага и PDF-сканы без текстового слоя. Типы документов разные: письма, запросы, ходатайства, претензии, товарные накладные. Сейчас документ находят только по памяти о том, где он лежит, или перебором папок. При этом юрист помнит о документе что угодно: фамилию, номер, обрывок фразы, примерный смысл.

### 2.1. Бизнес-цели

| ID | Цель | Критерий достижения |
|---|---|---|
| BG-1 | Находить документ одним запросом по тому, что о нём помнишь | Recall@5 ≥ 80% (NFR-Q2) |
| BG-2 | Не добавлять юристу ручной работы | При добавлении документа нет ни одного поля для заполнения |
| BG-3 | Не допустить утечки данных клиентов | Документы, их текст и запросы не покидают сервер (NFR-S1…S7) |

### 2.2. Исходные требования заказчика

Получены на интервью с заказчиком. Остальные требования выведены из них.

| ID | Требование | Цель |
|---|---|---|
| CR-1 | Никакого ручного заполнения карточек документов | BG-2 |
| CR-2 | Одна строка поиска, которая понимает любой запрос | BG-1 |
| CR-3 | Полностью локальная работа, без облаков и внешних API | BG-3 |

## 3. Заинтересованные стороны

| Роль | Интерес | Как взаимодействует |
|---|---|---|
| Юрист (заказчик, единственный пользователь) | Быстро найти документ, не разбираясь в системе | Страница поиска в браузере |
| Администратор (разработчик) | Установка, обновление, запуск обработки, диагностика | Командная строка, Docker, журналы |
| Клиенты юриста | Сохранность их персональных данных | Не взаимодействуют; их интересы закрывают NFR-S |

## 4. Границы

**MVP:**
- OCR PDF-сканов на русском языке;
- очистка текста, в том числе замена латинских букв-двойников;
- хранение в SQLite и полнотекстовый поиск FTS5 с русской морфологией;
- локальная страница поиска (Streamlit): строка поиска, результаты с фрагментами, открытие скана;
- автоматическая обработка новых сканов из папки.

**После MVP:** поиск по смыслу (эмбеддинги), автоматические карточки документов, фильтры по типу и дате, Docker и установка на сервер заказчика.

**Не входит:** облачные сервисы и внешние API; редактирование документов и ведение дел; рукописный текст; доступ из интернета; несколько пользователей с разными правами.

## 5. Ограничения и допущения

| ID | Ограничение | Следствие |
|---|---|---|
| C-1 | Сервер: Intel Xeon D-1521 (4 ядра, 8 потоков), 16 ГБ памяти, без видеокарты для ИИ | Без vision-моделей; LLM — только ночью и как отключаемая опция |
| C-2 | Сервер одновременно работает файловым сервером | Лимиты ресурсов, массовая обработка — ночью |
| C-3 | Сервер на Ubuntu, разработка на Windows | Переносимость через Docker |
| C-4 | В документах персональные данные клиентов | Разработка и репозиторий — только на демо-данных |

| ID | Допущение (проверить у заказчика) | Если неверно |
|---|---|---|
| A-1 | В архиве до 50 000 страниц | Пересчитать срок первичной обработки (NFR-P3) |
| A-2 | Сканы — PDF от 150 dpi | Качество ниже NFR-Q1 |
| A-3 | Новые сканы кладутся в одну известную папку | Нужна настройка нескольких папок |
| A-4 | Пользователь один | Нужны учётные записи и роли |

## 6. Функциональные требования

Критерии приёмки — в формате «Дано / Когда / Тогда», каждый переводится в тест.

### E1. Поступление и распознавание

**US-01. Автоматическая обработка новых сканов** · M
Как юрист, я хочу просто положить скан в папку, чтобы он стал доступен для поиска без заполнения полей.

- **AC-01.1** Дано: система работает. Когда: в папку сканов попадает новый PDF. Тогда: он находится поиском в срок по NFR-P2.
- **AC-01.2** Дано: файл уже обработан. Когда: обработка запускается снова. Тогда: файл не распознаётся повторно (проверка по хешу содержимого).
- **AC-01.3** Дано: файл заменили новой версией с тем же именем. Когда: запускается обработка. Тогда: распознаётся новая версия, старый текст в базе заменяется.
- **AC-01.4** Дано: файл в папке сканов. Когда: идёт обработка. Тогда: файл не изменяется, не перемещается и не удаляется.

**US-02. Первичная обработка архива** · M
Как администратор, я хочу прогнать весь архив ночами, чтобы не замедлять файловый сервер днём.

- **AC-02.1** Дано: задано ночное окно (например, 22:00–07:00). Когда: окно заканчивается. Тогда: новые файлы архива не берутся в работу до следующего окна. Новые сканы по US-01 обрабатываются в любое время.
- **AC-02.2** Дано: обработка прервалась. Когда: её запускают снова. Тогда: она продолжается с необработанных файлов.
- **AC-02.3** Дано: идёт обработка. Когда: администратор смотрит журнал. Тогда: видно, сколько файлов обработано, сколько осталось, сколько с ошибками.

**US-03. Проблемные файлы** · M
Как администратор, я хочу видеть, какие файлы не обработались и почему, чтобы исправить их, а не потерять.

- **AC-03.1** Дано: повреждённый PDF или PDF с паролем. Когда: идёт обработка. Тогда: файл пропускается, в журнал пишутся путь и тип ошибки, остальные файлы обрабатываются.
- **AC-03.2** Дано: файл не PDF. Когда: идёт обработка. Тогда: файл пропускается с записью в журнале (поддержка JPG/TIFF — вопрос Q-5).
- **AC-03.3** Дано: средняя уверенность Tesseract по документу ниже порога (по умолчанию 60, настраивается). Когда: документ сохраняется. Тогда: он помечается как «плохо распознан».

**US-04. Очистка текста** · M
Как юрист, я хочу, чтобы ошибки распознавания не мешали поиску, чтобы находить документ по правильно написанному слову.

- **AC-04.1** Дано: в русском слове латинские буквы вместо похожих кириллических («Ha», «OOO»). Когда: текст очищается. Тогда: они заменены на кириллицу.
- **AC-04.2** Дано: слово полностью латинское («LLC», «email»). Когда: текст очищается. Тогда: оно не меняется.
- **AC-04.3** Дано: слово перенесено через дефис на новую строку. Когда: текст очищается. Тогда: части склеены.
- **AC-04.4** Дано: результат OCR. Когда: текст очищается. Тогда: сырой текст сохраняется рядом с очищенным для сравнения и переобработки.

### E2. Поиск

**US-05. Поиск по словам** · M
Как юрист, я хочу ввести фамилию или слово, чтобы найти все документы, где оно встречается.

- **AC-05.1** Дано: в документе «Петров». Когда: я ищу «петров». Тогда: документ найден.
- **AC-05.2** Дано: в документе «наследства». Когда: я ищу «наследство». Тогда: документ найден.
- **AC-05.3** Дано: в документе «Королёв». Когда: я ищу «Королев». Тогда: документ найден, и наоборот.
- **AC-05.4** Дано: запрос из нескольких слов. Когда: я ищу. Тогда: документы со всеми словами стоят выше документов с частью слов.

**US-06. Поиск по номеру** · M
Как юрист, я хочу найти документ по номеру дела, договора, накладной или ИНН.

- **AC-06.1** Дано: в документе «А40-12345/2025». Когда: я ищу «А40-12345/2025» или «12345/2025». Тогда: документ найден.
- **AC-06.2** Дано: в документе ИНН «7701234567». Когда: я ищу «7701234567». Тогда: документ найден.
- **AC-06.3** (S) Дано: в документе «№ 15-П». Когда: я ищу «№15П» или «15 П». Тогда: документ найден.

**US-07. Поиск по точной фразе** · M
Как юрист, я хочу искать фразу в кавычках, чтобы найти документ по запомнившейся формулировке.

- **AC-07.1** Дано: в документе «о назначении судебной экспертизы». Когда: я ищу `"назначении судебной экспертизы"`. Тогда: документ найден, а документы, где эти слова стоят порознь, — нет.

**US-08. Неудачный запрос** · M
Как юрист, я хочу понимать, почему ничего не нашлось, чтобы переформулировать запрос.

- **AC-08.1** Дано: по запросу ничего нет. Когда: показываются результаты. Тогда: выводится «Ничего не найдено» и подсказка: проверить написание, убрать часть слов или кавычки.
- **AC-08.2** Дано: пустой запрос или одни пробелы. Когда: я запускаю поиск. Тогда: поиск не выполняется, ошибки нет.
- **AC-08.3** Дано: в запросе спецсимволы (`*`, `"` без пары, `(`, `-`, `:`). Когда: я ищу. Тогда: ошибки синтаксиса FTS5 нет, символы трактуются как обычный текст.

**US-09. Поиск по смыслу** · C
Как юрист, я хочу описать документ своими словами, чтобы найти его, даже если не помню точных формулировок.

- **AC-09.1** Дано: ходатайство об отложении заседания. Когда: я ищу «просили перенести суд». Тогда: документ в первых 10 результатах.
- **AC-09.2** Дано: поиск по смыслу включён. Когда: я ввожу любой запрос. Тогда: результаты обоих видов поиска показываются одним списком, режим выбирать не нужно (CR-2).

### E3. Результаты

**US-10. Список результатов** · M
Как юрист, я хочу по списку сразу понять, тот ли это документ, чтобы не открывать каждый.

- **AC-10.1** Дано: есть результаты. Когда: они показываются. Тогда: у каждого видны имя файла, папка, дата файла и фрагмент текста с подсвеченными словами запроса.
- **AC-10.2** Дано: результатов больше 20. Когда: они показываются. Тогда: видны первые 20 и общее число, остальные — по кнопке «Показать ещё».
- **AC-10.3** Дано: документ помечен «плохо распознан» (AC-03.3). Когда: он в результатах. Тогда: рядом пометка, что в тексте возможны ошибки.

**US-11. Открытие скана** · M
Как юрист, я хочу открыть исходный PDF из результатов, чтобы прочитать оригинал.

- **AC-11.1** Дано: результат поиска. Когда: я нажимаю «Открыть». Тогда: исходный PDF открывается в браузере.
- **AC-11.2** Дано: совпадение на странице 7. Когда: я смотрю результат. Тогда: указан номер страницы. (S: PDF открывается сразу на ней.)
- **AC-11.3** Дано: файл переместили или удалили. Когда: я нажимаю «Открыть». Тогда: выводится «Файл не найден» с прежним путём.

**US-12. Фильтры по типу и дате** · C
Как юрист, я хочу оставить в результатах, например, только претензии за 2025 год, чтобы быстрее выбрать среди похожих. Зависит от US-13.

- **AC-12.1** Дано: у документов определены тип и дата. Когда: я выбираю фильтр. Тогда: остаются только подходящие документы.
- **AC-12.2** Дано: фильтры не выбраны. Когда: я ищу. Тогда: поиск идёт по всему архиву.

### E4. Карточки документов

**US-13. Автоматическая карточка** · C
Как юрист, я хочу видеть у документа тип, даты, номера, суммы и стороны, не заполняя их вручную (CR-1).

- **AC-13.1** Дано: распознанный документ. Когда: строится карточка. Тогда: поля заполняются регулярными выражениями и Natasha, без LLM.
- **AC-13.2** Дано: поле не определено. Когда: карточка показывается. Тогда: поле пустое, а не заполнено догадкой.

**US-14. Карточки с помощью локальной LLM** · W
Отключаемая ночная опция — только если US-13 окажется недостаточно точной. По умолчанию выключена.

### E5. Администрирование

**US-15. Состояние системы** · S
Как администратор, я хочу видеть состояние базы и очереди, чтобы понимать, всё ли работает.

- **AC-15.1** Дано: система работает. Когда: я запускаю команду состояния. Тогда: видны число документов и страниц, размер очереди, число ошибок, время последней обработки.

**US-16. Пересборка индекса** · S
Как администратор, я хочу перестроить поисковый индекс без повторного OCR, чтобы применить новые правила очистки или морфологии.

- **AC-16.1** Дано: в базе сохранён текст. Когда: запускается пересборка. Тогда: индекс строится из сохранённого текста, Tesseract не запускается.

**US-17. Резервная копия** · S
Как администратор, я хочу копировать базу одной командой, чтобы после сбоя не распознавать архив заново.

- **AC-17.1** Дано: база заполнена. Когда: запускается копирование. Тогда: создаётся согласованная копия (SQLite backup API) в папке из `.env`.

## 7. Нефункциональные требования

### Производительность

| ID | Требование | Проверка |
|---|---|---|
| NFR-P1 | Ответ на запрос — не дольше 2 с для 95% запросов при 50 000 страниц | Прогон контрольных запросов на синтетической базе такого объёма |
| NFR-P2 | Новый документ до 10 страниц находится поиском не позже чем через 10 минут после появления в папке | Замер на демо-документах |
| NFR-P3 | Скорость первичной обработки — от 300 страниц в час на сервере заказчика. При 50 000 страниц это около 170 часов, то есть примерно 19 ночей по 9 часов | Замер на 100 демо-страницах |
| NFR-P4 | Страница поиска открывается не дольше 5 с | Ручная проверка |

### Ресурсы

| ID | Требование | Проверка |
|---|---|---|
| NFR-R1 | Не более 2 ядер и 4 ГБ памяти; лимиты заданы в Docker | `docker stats` во время обработки |
| NFR-R2 | OCR и построение эмбеддингов идут с пониженным приоритетом | Конфигурация, журнал |

### Безопасность и конфиденциальность

| ID | Требование | Проверка |
|---|---|---|
| NFR-S1 | Нет обращений к внешним сервисам; модели и словари хранятся локально | Все функции работают с отключённым интернетом |
| NFR-S2 | Страница поиска доступна только с `localhost`; доступ по сети — только с паролем (Q-3) | `server.address = "localhost"` в `.streamlit/config.toml`; попытка зайти с другого компьютера |
| NFR-S3 | Телеметрия библиотек отключена | `browser.gatherUsageStats = false` |
| NFR-S4 | В журналах нет текста документов и запросов — только время, число результатов, длительность, ошибки | Поиск фамилии из демо-документа по файлам журнала: 0 совпадений |
| NFR-S5 | Сканы, база, модели и журналы лежат вне папки проекта, пути — в `.env` | `git status` после обработки чист |
| NFR-S6 | Папка сканов подключается только на чтение | Том Docker с флагом `:ro` |
| NFR-S7 | В репозитории только демо-данные: вымышленные документы и открытые обезличенные решения | Ревью перед каждым push |
| NFR-S8 | На сервер обновления приходят только через `git pull`; для приватного репозитория — deploy key без права записи | Инструкция по установке |

### Надёжность

| ID | Требование | Проверка |
|---|---|---|
| NFR-N1 | Ошибка в одном файле не останавливает обработку остальных | Тест с повреждённым PDF |
| NFR-N2 | Прерванная обработка продолжается с места остановки | Тест: прервать и запустить снова |
| NFR-N3 | Сбой не повреждает базу: запись в транзакциях, режим WAL | Остановить процесс во время записи, затем `PRAGMA integrity_check` |
| NFR-N4 | После перезагрузки сервера система запускается сама | `restart: unless-stopped` в Docker Compose |

### Качество

| ID | Требование | Проверка |
|---|---|---|
| NFR-Q1 | CER ≤ 2% для сканов от 150 dpi | `docs/ocr_evaluation.md`. Сейчас измерена доля совпадающих символов (98,7–99,6% на трёх таких документах); переход на CER запланирован |
| NFR-Q2 | Recall@5 ≥ 80% на 15–20 контрольных запросах | `docs/search_evaluation.md`: до и после морфологии |
| NFR-Q3 | Таблицы на плохих сканах (около 125 dpi) — известное ограничение. Цель — 70% номеров и сумм из таблиц находятся поиском | Замер на демо-накладных; сейчас совпадение символов 64,5% |

### Удобство

| ID | Требование | Проверка |
|---|---|---|
| NFR-U1 | Для поиска не нужно обучение: одна строка, поиск по Enter | Приёмочный тест, п. 4 раздела 8 |
| NFR-U2 | Интерфейс и сообщения — на русском, без технических терминов | Ревью интерфейса |
| NFR-U3 | Работает в обычном браузере без установки программ | Проверка в Chrome и Firefox |

### Сопровождаемость

| ID | Требование | Проверка |
|---|---|---|
| NFR-M1 | Установка на сервер: `git clone`, заполнить `.env`, `docker compose up` | Установка на чистую Ubuntu по инструкции |

## 8. Приёмка MVP

MVP принят, когда выполнено всё:

1. Истории с приоритетом M проходят критерии приёмки на демо-данных.
2. Проверены NFR-S1…S7.
3. Recall@5 ≥ 80% (NFR-Q2).
4. Заказчик сам нашёл 5 документов из 5 по своим запросам на тестовом наборе.
